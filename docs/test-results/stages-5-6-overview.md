# Испытания и документация: обзор результатов

Обзор объединяет выполненные проверки на 10 ноября 2026 года. Результаты относятся к указанным запускам и не заменяют проверку текущего состояния сервера.

| Проверка | Подтверждённый результат | Подробности |
| --- | --- | --- |
| Приложение и файлы | Проверены открытие сайта, вход, отклонение неверного токена, загрузка и скачивание файла. После пересоздания Uploader объект остался доступен. | [Приложение](stage-0-1.md), [повторная проверка](2026-11-10-api-load.md) |
| Восстановление | После удаления Pod frontend контроллер создал новый Pod, сайт ответил HTTP 200. После перезагрузки VM восстановились сервисы и сохранилось содержимое проверочного файла. | [Pod и приложение](stage-0-1.md), [перезагрузка](2026-11-07-startup-probes.md) |
| Мониторинг | Prometheus получал метрики четырёх целей, Grafana использовала его как источник данных; выражения дашбордов возвращали временные ряды. Правило `AppServiceDown` сработало и снялось в отдельном Prometheus на искусственной цели. | [Мониторинг](stage-2-monitoring.md), [проверка правила](2026-11-10-alert.md) |
| Логирование | События приложений найдены в Elasticsearch по `request_id`; проверены вход в Kibana и доступ к представлению данных. 10 ноября поиск по тому же идентификатору через внутренний API Kibana вернул три события; интерфейс Discover отдельно не проверялся. При запуске Elasticsearch после перезагрузки VM отправленные события впоследствии дошли до хранилища. | [Логирование](stage-3-logging.md), [перезагрузка](2026-11-07-reboot.md), [повторная проверка](2026-11-10-api-load.md) |
| Буфер логов | В отдельном процессе Vector доставил событие из дискового буфера после недоступности искусственного приёмника и принудительного перезапуска процесса. | [Проверка Vector](2026-11-10-vector.md) |
| Масштабирование | При ограниченной CPU-нагрузке Security автоматически перешёл с одной реплики на две и обратно; обе реплики собирались Prometheus. | [Проверка HPA](2026-11-10-hpa.md) |
| Небольшая нагрузка | k6 выполнил 40 запросов с недействительным токеном без ошибок. Повторный запуск дал около 0,992 запроса/с, среднюю задержку 7,84 мс и p95 14,30 мс; выполнены выборочные замеры CPU и RAM узла. | [Результаты k6](2026-11-10-api-load.md), [сценарий](../../tests/load/README.md) |

Архитектурная схема, скриншоты интерфейсов, инструкции и ограничения находятся в [README](../../README.md). Дальнейшие задачи приведены в [плане](../plan.md).

Отдельно не проверены поиск конкретного `request_id` через интерфейс Kibana Discover, контролируемый разрыв связи Vector с работающим Elasticsearch и срабатывание актуального правила `AppServiceDown` при отказе реального сервиса в кластере. Локальные проверки Vector и Prometheus не подтверждают эти сценарии. Небольшой тест k6 не измерял успешные файловые операции или масштабирование под пользовательским трафиком; HPA проверялся отдельной CPU-нагрузкой.

Внешняя доставка уведомлений не настроена. Резервное копирование отложено; восстановление после потери хранилища не обеспечено. Работа полного стека на VM с 2 ГБ памяти не подтверждена.
