# Испытания и документация: обзор результатов

Этапы 5 и 6 исходного плана завершены в объёме перечисленных ниже проверок и документации; проверка Discover дополнена 12 ноября 2026 года. Результаты относятся к указанным запускам и не заменяют проверку текущего состояния сервера.

| Проверка | Подтверждённый результат | Подробности |
| --- | --- | --- |
| Приложение и файлы | Проверены открытие сайта, вход, отклонение неверного токена, загрузка и скачивание файла. После пересоздания Uploader объект остался доступен. | [Приложение](stage-0-1.md), [повторная проверка](2026-11-10-api-load.md) |
| Восстановление | После удаления Pod frontend контроллер создал новый Pod, сайт ответил HTTP 200. После перезагрузки VM восстановились сервисы и сохранилось содержимое проверочного файла. | [Pod и приложение](stage-0-1.md), [перезагрузка](2026-11-07-startup-probes.md) |
| Мониторинг | Prometheus получал метрики четырёх целей, Grafana использовала его как источник данных; выражения дашбордов возвращали временные ряды. Правило `AppServiceDown` сработало и снялось в отдельном Prometheus на искусственной цели и в кластере при контролируемом сетевом отказе Uploader. | [Мониторинг](stage-2-monitoring.md), [изолированная проверка](2026-11-10-alert.md), [проверка в кластере](2026-11-12-alert.md) |
| Логирование | События приложений найдены в Elasticsearch по `request_id`; проверены вход в Kibana и доступ к представлению данных. 10 ноября поиск через внутренний API Kibana вернул три события; 12 ноября проверен поиск отдельного известного события по `request_id` в интерфейсе Discover. При запуске Elasticsearch после перезагрузки VM отправленные события впоследствии дошли до хранилища. | [Логирование](stage-3-logging.md), [перезагрузка](2026-11-07-reboot.md), [повторная проверка](2026-11-10-api-load.md), [Discover](2026-11-12-discover.md) |
| Буфер логов | При временном разрыве связи Vector с Elasticsearch в кластере событие найдено в буфере и после восстановления доставлено в Elasticsearch. Отдельно проверен буфер Vector с искусственным приёмником и перезапуском процесса. | [Проверка на кластере](2026-11-10-live-vector-outage.md), [изолированная проверка](2026-11-10-vector.md) |
| Масштабирование | При ограниченной CPU-нагрузке Security автоматически перешёл с одной реплики на две и обратно; обе реплики собирались Prometheus. | [Проверка HPA](2026-11-10-hpa.md) |
| Небольшая нагрузка | k6 выполнил 40 запросов с недействительным токеном без ошибок. Повторный запуск дал около 0,992 запроса/с, среднюю задержку 7,84 мс и p95 14,30 мс; выполнены выборочные замеры CPU и RAM узла. | [Результаты k6](2026-11-10-api-load.md), [сценарий](../../tests/load/README.md) |

Архитектурная схема, скриншоты интерфейсов, инструкции и ограничения находятся в [README](../../README.md). Дальнейшие задачи приведены в [плане](../plan.md).

При проверке алерта контейнер Uploader не останавливался: проверялся сетевой отказ. Длительный отказ, заполнение буфера и поздние повторы событий не проверялись. Небольшой тест k6 не измерял успешные файловые операции или масштабирование под пользовательским трафиком; HPA проверялся отдельной CPU-нагрузкой.

Внешняя доставка уведомлений не настроена. Резервное копирование отложено; восстановление после потери хранилища не обеспечено. Работа полного стека на VM с 2 ГБ памяти не подтверждена.
