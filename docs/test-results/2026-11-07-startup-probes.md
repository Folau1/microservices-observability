# Проверка стартовых проб: 7 ноября 2026

Для MinIO, Security, Uploader и Telegraf добавлены startupProbe с 36 попытками с интервалом пять секунд; это даёт около трёх минут на запуск. Проверки используют локальные endpoints процессов; у Uploader `/health/live` не зависит от MinIO. Прежние readiness и liveness сохранены. Для управляемого K3s Traefik проверка `/ping:8080` добавлена через отдельный HelmChartConfig после сравнения рендера установленного chart.

Перед установкой server-side diff подтвердил, что спецификации четырёх изменённых рабочих нагрузок отличаются только startupProbe. Рабочие нагрузки последовательно обновлены, а Traefik прошёл rollout. Авторизация и чтение существующего файла проверены, его содержимое совпало с контрольной суммой до обновлений.

Затем выполнен перезапуск VM. Выделенный том логов подключился с прежним UUID. MinIO, Security, Uploader, Telegraf и Traefik достигли готовности без дополнительных перезапусков из-за liveness: у каждого счётчик вырос на один при перезагрузке, с предыдущим состоянием `Unknown` и кодом 255. При предыдущем запуске все пять получили дополнительные перезапуски из-за liveness. Это результат одного испытания и не гарантия для любой нагрузки.

После запуска проверены сайт и Kibana из Windows, вход и представление данных Kibana, сохранность объекта, доставка новых логов, четыре доступных target Prometheus и работа агента TeamCity. Elasticsearch и Kibana стартовали заметно медленно: Kibana достигла готовности примерно через десять минут после загрузки ОС. На момент проверки у VM объёмом 4,7 ГиБ было около 1,1 ГиБ доступной памяти, использовался swap около 326 МиБ; корневой раздел был занят на 83%. Дисковая инициализация создавала заметную нагрузку. Эти показатели не подтверждают запас под длительной нагрузкой.
