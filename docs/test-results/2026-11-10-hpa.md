# Проверка масштабирования: 10 ноября 2026

Для Security проверено автоматическое масштабирование HPA по CPU на работающем узле K3s. Исходное состояние — один готовый Pod, предел HPA — две реплики. В одном Pod запущен ограниченный CPU-процесс: максимум 90 секунд и 10 секунд процессорного времени. Это проверка механизма масштабирования, а не нагрузочный тест пользовательских запросов.

Примерно через 78 секунд работали две готовые реплики; к 96-й секунде Prometheus показывал обе их цели как доступные. Серверный `dry-run` применения Deployment при двух репликах сохранил число реплик равным двум. После завершения CPU-нагрузки HPA автоматически вернул одну готовую реплику; полный цикл занял около 425 секунд.

Во время наблюдения доступная память не опускалась ниже 842268 КиБ, использованный swap составлял примерно 427–428 тысяч КиБ. Проверялись готовность узла, компонентов и сайта, свободное место, память, swap и дисковое давление; при выходе за заданные границы сценарий предусматривал остановку и ограничение HPA одной репликой.

Эта проверка не измеряла RPS, задержки или ошибки под пользовательской нагрузкой. Отдельно проведён [короткий API-тест](2026-11-10-api-load.md) с замером RPS и задержек; он не предназначен для проверки масштабирования. Показатели потребления — моментальные и не подтверждают запуск всего стека на VM с 2 ГБ.
