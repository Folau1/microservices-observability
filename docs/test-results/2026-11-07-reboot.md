# Проверка восстановления после перезапуска: 7 ноября 2026

Проверка выполнена на существующей виртуальной машине `node2` с пределом памяти 5000 МБ. Сервер был перезагружен; после повторного подключения идентификатор загрузки изменился. В журнале сервера используется UTC, местное время пользователя — Екатеринбург, UTC+5.

После запуска подтвердили, что выделенный том ext4 для данных Elasticsearch и буфера Vector снова смонтирован, а его UUID совпадает с идентификатором до перезапуска. Все Pod приложения, мониторинга и логирования достигли состояния `1/1`; агент TeamCity также запустился.

## Проверка данных и сервисов

- Содержимое проверенного файла совпало с исходным по SHA-256 до и после перезапуска.
- В Elasticsearch обнаружены по три события с идентификаторами запросов до и после перезапуска. Второй запрос был выполнен во время запуска Elasticsearch. Этот результат подтверждает доставку проверенных событий, но не гарантирует доставку во всех сценариях сбоя.
- Kibana после восстановления вернула HTTP 200 для страницы входа. Проверены вход через POST с созданием сессии и доступ к представлению данных: HTTP 200.
- Все четыре цели Prometheus находились в состоянии `up`, активных оповещений не было.
- Elasticsearch сообщил состояние `yellow`: все основные шарды активны, одна реплика не распределена на единственном узле. Такая конфигурация не обеспечивает отказоустойчивость.

## Наблюдения и ограничения

Во время запуска при высоком дисковом давлении liveness-проверки по одному разу вызвали перезапуск контейнеров Security, Uploader, MinIO, Telegraf и Traefik. В последних состояниях контейнеров `OOMKilled` не зафиксирован; одного этого наблюдения недостаточно для установления причины медленного старта. Готовность Kibana зафиксирована примерно через 7–8 минут после команды перезапуска; это верхняя оценка по периодическим проверкам.

При замере после восстановления Ubuntu показывала 4,7 ГиБ общей памяти, около 1 ГиБ доступной RAM и 224 МиБ используемого swap. На корневом разделе оставалось около 4,5 ГиБ свободного места при заполнении 83 %. Это моментальные значения; под нагрузкой они могут измениться.

Проверка не заменяет полноценные испытания отказов и восстановления из резервной копии. Автоматическое оповещение о заполнении отдельного тома логов ещё не настроено.
