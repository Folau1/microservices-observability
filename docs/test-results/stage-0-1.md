# Этапы 0–1: фактический результат

Дата проверки: 5 ноября 2026 года. На одноузловом K3s проверены доступ к сайту, авторизация, загрузка и скачивание тестового файла и отдельные сценарии восстановления.

## Этап 0: окружение

- Папка `%USERPROFILE%\Documents\Project_home\Project\microservices-observability` существовала и содержала только `.git`. Git 2.55.0.windows.3; `git status --short --branch` показал ветку `main` без коммитов; `git remote -v` — указанный пользователем GitHub-репозиторий. На момент проверки push не выполнялся.
- SSH на `192.168.1.151:22` работает с выделенным для проекта ключом, закрытая часть хранится на Windows вне репозитория. Открытый ключ сервера ED25519 проверен по отпечатку, полученному пользователем в консоли сервера. Строгая проверка ключа включена.
- Для развёртывания временно выдавалось правило passwordless sudo; после завершения оно удалено, а таймер его удаления остановлен. Выделенный SSH-ключ хранится вне репозитория.
- Сервер `node2`: Ubuntu 24.04.4 LTS, x86_64, 3 vCPU, 6,6 ГиБ RAM; на момент первоначальной проверки 5,8 ГиБ RAM было доступно. Swap 2 ГиБ сохранён; K3s запущен с `fail-swap-on=false`. На корневом разделе первоначально свободно около 8,8 ГиБ; после согласованного расширения LVM на 8 ГиБ — около 15 ГиБ.
- До установки K3s не обнаружен; Docker и контейнер TeamCity agent уже работали. Порт 80 был свободен. TeamCity agent оставался запущенным после перечисленных изменений.
- Windows имеет Docker CLI 29.8.1, но обращение к Docker Engine завершилось ошибкой: Linux engine недоступен. `kubectl` установлен; Helm не обнаружен в PATH. Python 3.14.8 доступен.
- Windows `ssh-keyscan` не смог согласовать алгоритм обмена ключами; Git for Windows `ssh-keyscan` получил открытый ключ, а `ssh-keygen -lf ... -E sha256` подтвердил предоставленный отпечаток. Это не потребовало изменения серверной конфигурации.

## Этап 1: подготовка и локальная проверка

- Созданы три сервиса, Dockerfile, API-тесты, манифесты Kubernetes и скрипты. Перечень файлов можно получить командой `git status --short --untracked-files=all` из папки репозитория.
- На сервере установлен K3s v1.37.2+k3s1. Единственный Node находится в состоянии Ready; Traefik, CoreDNS, local-path-provisioner и Metrics Server достигли Ready. Созданы namespace приложения и Kubernetes Secret со случайными значениями. Секреты в отчёт и репозиторий не включены.
- Все четыре образа собраны и импортированы в K3s, манифесты применены. PVC с запросом 5 ГиБ находится в состоянии Bound; все четыре Pod готовы, рестартов на момент проверки 0. Запрос PVC не является жёсткой квотой: local-path-provisioner не ограничивает реальное потребление, необходимо следить за свободным местом.
- С Windows через Traefik проверены главная страница (HTTP 200), вход и проверка токена; неверный токен отклонён с HTTP 401. Синтетический файл загружен с HTTP 201, скачан с HTTP 200, содержимое совпало. Файл размером 5 МиБ + 1 байт отклонён с HTTP 413.
- Скрипт `scripts/smoke-test.py` на сервере завершился PASS, в том числе при повторном сквозном прогоне после исправления frontend. Объект `1adef944-2bea-4c67-98ec-73cd91294f0f` остался доступен после последовательного `rollout restart` Uploader и MinIO. Он сохранён в хранилище и автоматически не удаляется.
- Проверка сети: из Pod Security попытка TCP-подключения к MinIO вернула `connect_ex=111`, из Uploader — `connect_ex=0`. Метрики `/metrics` и структурированные JSON-логи с `request_id` проверены для Security и Uploader. Это отдельные проверки, а не полный аудит безопасности и наблюдаемости.
- Pod frontend удалён, контроллер создал новый, сайт вернул HTTP 200. Изначально старый frontend завершался около 30 секунд; после исправления обработки SIGTERM и обновления контрольное удаление заняло 2 секунды.
- При первом пересоздании Uploader сразу после `rollout status` наблюдался один HTTP 502; повторная проверка прошла. Добавлена задержка `preStop` 5 секунд; при следующей замене на фоне 150 небольших запросов все 150 получили ожидаемый HTTP 401, других кодов не было. Это ограниченный тест и не гарантирует отсутствие перерывов.
- Ограничение доступа для TCP 6443/10250 и UDP 8472 организовано отдельной цепочкой `CODEX_K3S_API`: для IPv4 дальнейшая обработка разрешена для loopback, локальной сети и сети Pod; для IPv6 — loopback. Остальные правила firewall продолжают действовать. Установлена служба `codex-k3s-api-firewall.service`; внешняя проверка доступности и проброса портов маршрутизатора не проводилась. При перезапуске этой службы из-за зависимости `Requires` кратковременно перезапустилась служба K3s; затем K3s снова стала active, а Node — Ready. ВМ не перезагружалась, TeamCity продолжал работать.
- Выполнен `kubectl kustomize work/project/kubernetes/base`: код 0. Команда проверяет построение манифестов, но не состояние и совместимость целевого кластера.
- Выполнен `python -m pytest work/project/tests -q` в изолированном Python-окружении с прямыми версиями зависимостей из requirements: **9 passed**, 51 предупреждение об устаревающих интерфейсах на Python 3.14. Использовались имитации S3 и проверки токенов; реальные MinIO, сеть и Kubernetes не участвовали. Проверены раздельные probes и доступность liveness при медленном обращении к хранилищу.
- Выполнены `bash -n` отдельно для каждого скрипта: ошибок синтаксиса нет. Это не проверка исполнения и прав в Linux.
- Синтаксис JavaScript интерфейса проверен `node --check`; маршруты и JSON-логирование frontend также проверены без сетевого сокета. Среда sandbox блокировала локальный сокет; позднее HTTP-ответ главной страницы через сервер проверен с Windows. Ручная проверка всех функций интерфейса пока не подтверждена.
- До установки пакетов в изолированное окружение PyPI в sandbox не разрешался; загрузка зависимостей и pytest выполнены вне этого ограничения. Python, пакеты и временные файлы находились в рабочем каталоге, системные пакеты не устанавливались.
- MinIO собран из закреплённого исходного коммита релиза 2025-10-15 с исправлением безопасности с помощью официального архива Go с проверкой SHA-256, во временном изолированном каталоге Linux x86-64, без установки Go в систему. Финальный образ использует `python:3.12-slim`; исходный репозиторий MinIO архивирован.

Логин `demo`, пароль можно посмотреть в локальной консоли сервера командой `sudo cat /home/codex/.local/state/microservices-observability/secrets/DEMO_PASSWORD`; не отправляйте его в чат.
