# Проверка алерта в отдельном Prometheus

Скрипт запускает отдельный локальный экземпляр Prometheus с настоящим файлом `monitoring/prometheus/alerts.yml` из репозитория и своей временной базой. Он включает и выключает локальную искусственную цель метрик и проверяет переходы `up=1` → `up=0` → `AppServiceDown firing` → `up=1` → отсутствие алерта. Существующий кластер, его конфигурация и пользовательские данные не затрагиваются.

Нужны Python 3 и исполняемый файл Prometheus, совместимый с правилами проекта (проверялся Prometheus 3.15.1). Из корня репозитория:

```powershell
python monitoring/tests/test-alert-isolated.py --prometheus 'C:\путь\к\prometheus.exe'
```

В Linux вместо пути к `.exe` укажите путь к исполняемому файлу Prometheus; если он уже в `PATH`, параметр `--prometheus` можно опустить. Оба временных HTTP-сервера слушают только `127.0.0.1` на автоматически выбранных портах. По окончании скрипт останавливает их и удаляет временные файлы. Из-за интервала вычисления и времени удержания правила проверка обычно занимает около минуты.

Эта проверка исполняет действующее выражение на искусственной цели; она не подтверждает отказ настоящего приложения, работу обнаружения Pod в Kubernetes или доставку внешних уведомлений. Проверки остальных сценариев правила находятся в `monitoring/prometheus/rules-test.yaml` и выполняются с помощью `promtool test rules`.
