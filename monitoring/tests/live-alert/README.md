# Проверка алерта на работающем кластере

Сценарий на короткое время делает Uploader недоступным через Traefik и для сбора метрик Prometheus. В этот период запросы к загрузчику через шлюз завершаются ошибкой; остальное приложение и сохранённые файлы скрипт не изменяет. Он проверяет ответ шлюза 502/503/504, состояние цели `down` и срабатывание `AppServiceDown`, а после восстановления — ответ 401 без токена, состояние цели `up` и снятие алерта.

Сценарий рассчитан только на описанный узел `node2`: Linux, root, systemd, `iptables-nft`, K3s, смонтированный том логов и готовые одиночные Pod Traefik, Prometheus и Uploader. Имена, namespace и порты должны соответствовать текущей конфигурации проекта. Проверка других окружений не проводилась.

## Запуск

Это **изменение работающего firewall и временное прерывание доступа к Uploader**. Запускайте только вручную, когда простой допустим, из корня проверенной копии репозитория на узле Linux:

```bash
sudo python3 -c 'import sys; sys.path.insert(0, "monitoring/tests/live-alert"); import alert_guard; alert_guard.experiment()'
```

Прямой запуск файла `alert_guard.py` заблокирован. До изменения скрипт проверяет готовность узла и сервисов, свободные ресурсы, исходное состояние цели и отсутствие алерта. Два точных firewall-правила разрешают проверять отдельно источники Traefik и Prometheus; до установки каждого правила создаются независимые systemd-таймеры его удаления. Скрипт повторно сверяет идентичность Pod и состояние узла, затем удаляет оба правила и наблюдает восстановление. Если возникнет ошибка очистки, соответствующий таймер остаётся активным.

При сообщении `MANUAL ACTION` проверьте только временные единицы `codex-vector-cut-*.timer` и одноимённые каталоги `/run/codex-vector-cut-*`, а также правила с соответствующими уникальными метками в `sudo iptables -w 5 -S FORWARD`. В каждом каталоге находится `cleanup.sh` для удаления только своего точного правила. Не отключайте таймер, пока удаление правила не подтверждено. Автоматический откат при перезагрузке отдельно не проверялся и зависит от того, сохраняются ли правила firewall на конкретном сервере.

## Локальные тесты

Тесты ниже не изменяют кластер и используют поддельные команды firewall и systemd. Для проверки обработки сигналов необходим Linux:

```bash
python3 -m unittest discover -s monitoring/tests/live-alert/tests -v
```

Сценарий использует ранее проверенные функции восстановления из `logging/vector/tests/live-guard/guard.py`; отдельная копия этих функций не хранится.
