# Проверка буфера Vector

Из корня репозитория запустите Python 3, указав путь к установленному Vector:

```powershell
python logging/vector/tests/test-buffer-isolated.py --vector 'C:\путь\к\vector.exe'
```

Для проверки использовался Vector 0.61.0. Сценарий создаёт временную конфигурацию и данные вне репозитория, отправляет одно событие в Elasticsearch sink с дисковым буфером, пока локальный искусственный приёмник недоступен, и ожидает сообщения о повторной попытке. После принудительного завершения и перезапуска Vector он включает приёмник и проверяет доставку этого же события без повторной отправки. Сервер слушает только `127.0.0.1`; временные данные удаляются в конце. При неудаче возвращается ненулевой код.

Приёмник только имитирует ответ Elasticsearch Bulk API. Используются локальный источник `stdin` и HTTP без аутентификации; реальные Kubernetes, Elasticsearch, Vector, TLS, секреты и данные не затрагиваются. Перезапуск процесса не является проверкой перезагрузки VM или отказа сети на действующем сервере.
